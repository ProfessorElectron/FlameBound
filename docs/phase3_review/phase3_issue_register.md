# Phase 3 Issue Register

| ID | Severity | Affected file/function | Finding and impact | Recommended correction | Fixed? |
|---|---|---|---|---|---|
| P3R-01 | MEDIUM | `modelling/atmospheric.py::convert_pressure` | Multiplying by source factor before division could overflow for large same-unit conversions whose result is representable. | Divide conversion factors first; then multiply and check finite output. | **Yes** |
| P3R-02 | HIGH | `modelling/atmospheric.py::convert_pressure`, `oxygen_partial_pressure`, `oxygen_mass_fraction` | Underflow could silently return numeric zero for a mathematically positive result, confusing it with true zero. | Reject positive-input underflow to zero with explicit `ValueError`. | **Yes** |
| P3R-03 | HIGH | `AtmosphericCondition`, `InputProvenance` | A field could claim `MEASURED` without field-level source record; status could be manually asserted. This risks laundering user inputs as observations. | Require source-record ID/locator and matching field-level measured provenance. Backend must additionally authenticate references server-side. | **Partly**: model shape fixed; server authentication remains open. |
| P3R-04 | HIGH | `CalculationResult.to_dict`, `_json_value` | Nonfinite numbers or non-string keys could escape into invalid/non-standard JSON. | Recursively reject NaN/infinity, unsupported types and non-string keys. | **Yes** |
| P3R-05 | MEDIUM | `compare_atmospheres` | `reference_pressure_unit or pressure_unit` silently treated an explicitly empty unit as omitted, possibly misinterpreting pressure. | Fallback only when value is `None`; reject empty/unknown units. | **Yes** |
| P3R-06 | HIGH | `modelling/data_harmonization.py::oxygen_fraction` | A truthy string such as `"false"` could pass the volume-percent verification gate. | Require an actual Boolean. | **Yes** |
| P3R-07 | MEDIUM | `InputProvenance`, `AtmosphericCondition` | Percent raw oxygen or pressure whose raw unit differed from normalized unit could lack an explicit normalization method, losing conversion traceability. | Require normalization metadata for percentage input and mismatched pressure units; expose it in result. | **Yes** |
| P3R-08 | HIGH | `AtmosphericCondition.gas_basis_verified` | The Boolean is caller-trusted; a caller or AI can set it true without evidence. A dataclass cannot authenticate evidence. | API must not accept this field from AI. Construct it from a schema that only accepts mole fraction for hypothetical inputs, or a trusted verified source record for experimental inputs. | **No; API boundary requirement** |
| P3R-09 | HIGH | Legacy `convert_pressure`, `oxygen_partial_pressure`, `compare_atmospheres` | Numeric helpers lack provenance and explicit pressure/gas-basis fields and can bypass typed validation. Direct AI exposure would weaken safeguards. | Expose only typed `calculate_*` operations through backend; keep legacy functions for internal/backward-compatible numeric use and label them non-API. | **No; route policy required** |
| P3R-10 | MEDIUM | Legacy `oxygen_mass_fraction` | Former default diluent molar mass 28.014 was removed; calls with no verified diluent now fail, a behavioral compatibility break. Silent nitrogen assumption was scientifically unsafe. | Keep current safe behavior, document exact migration, and search downstream consumers before release. Repository search found only tests/internal calls. | **Documented; external callers unknown** |
| P3R-11 | MEDIUM | `BinaryDiluent`, future mass-fraction API | Only binary O2 plus one named diluent is modeled. Multi-component diluent mixtures cannot be represented faithfully. | Keep scope explicit. Add a composition-vector solver only after defining component fractions, molar masses and verification rules. | **No; intentional limitation** |
| P3R-12 | MEDIUM | `backend/app/main.py`, API contract | Requested `/api/health` and atmospheric routes do not exist; only `/health` exists. | Implement separately with strict Pydantic schemas and call typed engine functions without reimplementing equations. | **No; this review did not implement routes** |
| P3R-13 | MEDIUM | `InputProvenance` and backend source lookup | Source IDs/locators are shape-checked but cannot be authenticated by the Python module. Fake references could appear verified if a caller is trusted. | Resolve source IDs against a server-controlled registry and assign verification status server-side. | **No; requires backend source registry** |
| P3R-14 | LOW | `CalculationResult` | Results have no explicit schema/engine version, which complicates persisted responses across releases. | Add a versioned response contract before storing or supporting multiple API versions. | **No; not blocking isolated calculations** |
| P3R-15 | LOW | Test environment | `pytest` is absent, though tests use `unittest`; the active environment has no repo venv. | Continue running full unittest discovery; establish the intended project environment in CI when available. | **No; environment limitation documented** |
| P3R-16 | MEDIUM | `calculate_oxygen_mass_fraction` | The typed mass-fraction function required `AtmosphericCondition`, which also required total pressure even though the binary mass-balance equation does not use pressure. This could force an API to request irrelevant or fabricated data. | Add `OxygenComposition` and let the mass-fraction operation accept composition directly; retain `AtmosphericCondition` compatibility. | **Yes** |

Severity reflects risk if the affected interface is used in an exposed API, not only current repository behavior. No raw NASA data or harmonised rows were changed.
